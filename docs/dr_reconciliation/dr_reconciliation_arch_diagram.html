Common recon pattern

build this once — every asset plugs into the same skeleton

The engine loop, scope resolution, classification, persistence, and alerting are shared. Each object type implements one small AssetReconciler — only four things differ per asset: how it reads, how it keys objects for P↔S matching, what it puts in the signature, and any asset-specific diff nuance. Classification precedence + readiness rollup are common (see the build spec).

# ---- COMMON (shared by all 10 assets) ----------------------------------
class AssetReconciler:                 # one subclass per object type
    object_type: str
    def read(self, client, scope) -> dict[key, Sig]: ...   # SAME code, primary & secondary client
    def match_key(self, obj) -> str:   ...   # how P↔S objects are paired
    def signature(self, obj) -> Sig:  ...   # fields to compare / hash
    def diff(self, p, s, ctx) -> str: ...    # asset-specific rule → raw status

def run(scope, primary, monitor):        # the shared engine loop
    rows = []
    for R in RECONCILERS:                 # the 10 asset reconcilers
        P = R.read(primary, scope)         # ② {key: primary_sig}
        S = R.read(monitor, scope)         # ③ {key: secondary_sig}  (read-only, via monitor)
        for key in P.keys() | S.keys():
            status = classify(R.diff(P.get(key), S.get(key), ctx))   # ④ common precedence + severity
            rows.append(record(R.object_type, key, P.get(key), S.get(key), status))
    persist(rows)                          # ⑤ MERGE → dr_recon_* ; ⑥ dashboard ; ⑦ alerts

Common precedence (first match wins): UNSUPPORTED → FAILED → MISSING → DRIFTED → LAGGING → IN_SYNC. Direction (primary vs secondary) is read once from effective_primary_region, so failover/failback reuse the same reconcilers with roles swapped.
